# Eval Optimization Experiments

Append-only ledger of prompt-optimization experiments, owned by the driver in the **main checkout** — worktree copies are disposable and invisible to each other, so results must be recorded here. One entry per experiment, newest at the bottom. See `eval/GOAL.md` for the protocol. Braintrust (project `opinions-agent`) holds the full scores and traces; this file is the narrative history so the loop can build on prior results without a round-trip.

Cost note: Braintrust's `estimated_cost` is accurate for runs made with thinharness ≥ 0.5.1 (bumped 2026-07-05), which reports OpenAI's `cached_tokens` detail. Experiments recorded before that read ~1.8x high — every input token priced at full rate — so a full 9-week run shown as ~$10 actually cost ~$5.

**Current best:** `exp/critic-2` (anchor-examples lineage + omission-only critic tool; promoted 2026-07-05 on the critic-2-r4 addendum evidence. The 2026-07-06 lean-critic-2 leanness promotion was reversed by Ryan the same day — a 4% prompt reduction is not worth trading the stronger point estimate and precision margin. The critic itself was retained by the 2026-07-12 no-critic ablation: it is a floor lever, not a mean lever.)

**Score to beat:** 0.865 mean `opinion_quality` under scoring_version `2026-07-10-coverage-concepts` (pooled rescores `critic-2-r{1..4}-rs-0710f`: 0.887 / 0.846 / 0.806 / 0.919; floor 0.806), holding replicate-mean `evidence_precision` ≥ 0.50. Fresh runs are graded under the current scoring version, so they compare against this, not the old-scoring numbers. Screen runs compare against the per-model subset baselines pinned in `eval/STATUS.md`. On promotion, update this to the new best's replicate mean.

## Entry format

Each entry records:

- **Experiment** — the variant name. In Braintrust each run is `<variant>-r<N>` (rescores add `-rs-<date>`), with `variant`, `run`, and `scoring_version` metadata for filtering and grouping.
- **Hypothesis** — the change and why it should help.
- **Changed** — one-line summary of the `prompts.py` / `RULES.md` edit.
- **Scores** — mean `opinion_quality` (primary), `evidence_recall`, `evidence_precision`.
- **Verdict** — promoted or reverted, and why.
- **Learned** — anything that should steer the next experiment.

### judge-variance probe (diagnostic, not a prompt experiment)

- **Question:** How much of the run-to-run `opinion_quality` spread (keep-the-list: 0.487/0.698/0.660) is judge inconsistency rather than proposal variance?
- **Method:** (a) Re-judged identical stored outputs with the proxy cache disabled (`x-bt-use-cache: never` — note `eval rescore` alone is useless for this: the Braintrust proxy caches temperature-0 judge calls, so a plain rescore returns bit-identical verdicts). keep-the-list run 1 judged 3x, run 2 judged 3x. (b) For the 17 targets whose verdicts flip across keep-the-list runs 1–3, compared the matched proposal texts (difflib similarity) to attribute each flip.
- **Findings:** (a) Judge noise on identical outputs is real but small: run 1 scored 0.4875 all 3 times (0 flips, matches the stored 0.487); run 2 scored 0.635/0.635/0.667 vs 0.698 at run time — a ~3–6pt session-level drift from 1–2 borderline verdicts per judging (W06-03 was one). (b) Of the 17 cross-run flip targets, 16 had materially different matched proposal texts (sim 0.01–0.56) → proposal variance; 1 (W05-03, sim 1.0, pass/pass/unmatched) was a greedy-matching artifact, not a judge flip.
- **Implications:** The 0.21 keep-the-list spread is dominated by proposal variance, not the judge; the protocol's ±3–6pt noise band is exactly the judge+matching floor and stays valid. Borderline proposals are where the judge wavers — decisive proposals judge deterministically. Comparing runs judged on different days carries up to ~6pt of judge-session drift, so same-day replicates are the cleanest comparisons; a variant's gain must clear the band regardless. Fixing the variance means stabilizing the agent's proposals (e.g., the planned fidelity-leanness pass), not the judge.

### opinion_attempted metric (eval infrastructure, not a prompt experiment)

- **What:** A second LLM judge alongside `opinion_quality`, landed on main (`f81a233`). `opinion_attempted` is the lenient layer of the funnel: a target counts as attempted when its matched proposal expresses the same central claim, even if it dropped supporting concepts, named examples, numbers, or caveats. A quality pass implies attempted, so the lenient judge only runs on matched-but-failed targets (~10-15 extra sonnet calls per run). Both judges share one match-and-judge pass per week, so matching is never duplicated and the two metrics can't disagree about which proposal a target matched. The metric triad now reads as a funnel: evidence_recall (citations used) → opinion_attempted (right claims proposed) → opinion_quality (right claims written completely); fidelity-given-attempted is quality ÷ attempted, computable from the two.
- **Why:** The attempted-vs-faithful probe on anchor-examples showed coverage is stable/near-ceiling (31-33 of 33 targets attempted across runs) while concept-fidelity is the volatile layer (17-22 faithful). Attempted is not recall restated: recall was 1.000 on runs where attempted was 31/33 — merge collisions and different-claim writes give perfect recall with missed targets.
- **Validation:** Backfilled `anchor-examples-r2` via `eval rescore` → `anchor-examples-r2-attempted`: opinion_quality reproduced bit-identically (0.5083, proxy cache hit) and opinion_attempted 0.975 matches the probe's 32/33. `eval rescore` can backfill the metric onto any historical experiment; the inspector now reports it.

### critic

- **Hypothesis:** An isolated-context critic tool (claude-opus-4-8 via the Braintrust proxy) reviewing each draft opinion against its cited evidence — rubric: central claim, mechanism, named specifics, whole claim, standalone — should catch the per-proposal concept-drop lottery before proposals are sent, stabilizing the fidelity layer the attempted-vs-faithful probe isolated (attempted ~0.97, faithful 0.51–0.68).
- **Changed:** New `critique_opinion_draft` ToolSpec in `agent.py`: the agent passes its exact draft text + evidence_ids, the host looks up the evidence texts from selected-highlights.jsonl and calls opus-4-8; the rubric lives only in the host-side `CRITIC_PROMPT` (`prompts.py`), plus a "critique each draft before sending, use the final wording verbatim" tool-use bullet. Branched from `exp/anchor-examples` (which already includes the lean-reads efficiency changes), `opinion_attempted` scorer cherry-picked on top. Commit `4209ea3`.
- **Scores:** opinion_quality **0.452** (vs 0.615 score to beat; below the base's worst replicate 0.508). opinion_attempted 0.969, evidence_recall 0.979, evidence_precision 0.522 (+0.015 vs base). Cost of the loop: 137.6k prompt tok/wk (vs 92.6k lean-reads), est $1.63/wk, tool_calls 11.7/wk (~2x), duration 110s/wk.
- **Verdict:** Not promoted; stopped at screen per protocol.
- **Learned:** (a) The critic was heavily used and did its intended job on the flaky class: 88 calls across 9 weeks, 77% REVISE rate, and 7 targets up — mostly the historically flaky concept-drop set (W05-01, W08-04, W10-02/03, W12-01, W13-03, W13-05). (b) But it broke six previously 3/3-stable targets (W05-03, W06-02/03/04, W08-02, W11-01) through three trace-visible mechanisms: **evidence-context asymmetry** — the critic sees only the cited snippet, so it flagged legitimately source-read content as "fabricated... remove it" (W06 ZIRP and vault drafts), directly fighting the bounded-read workflow; **snippet-literalism displacing canon concepts** — demands for the snippet's exact vocabulary and every snippet detail pushed out concepts the draft already carried (W06-03's draft contained "scoping"; the critique-driven rewrite chasing "Sierra"/"onsite" deleted it and the judge failed the final text on exactly that concept); **rewrite churn** — at a 77% REVISE rate nearly every stable draft got re-rolled. (c) The redesign this implies: align the critic with the scoring asymmetry — omission-only (flag missing mechanism/specifics/claim-parts; never demand removals or rewording, since extra content never hurts and the agent reads sources the critic cannot see), no vocabulary pedantry, default READY when unsure, and tell the agent to add flagged concepts by tightening wording rather than deleting others. (d) Moving the fidelity rules out of the main prompt and into the critic (the proposed split) is higher-risk until (c) is proven: in its current form, critique-dominated rewriting degrades canon alignment.

### opinion_brevity metric (eval infrastructure, not a prompt experiment)

- **What:** A deterministic fifth scorer alongside the judges: per week, mean proposal word count vs mean golden-target word count, scored `min(1, target_mean / proposal_mean)` — 1.0 at or below the golden length, 0.5 at twice it. Raw means live in the score metadata. Reference metric, not a gate: quality already guards under-writing, so shorter than golden caps at 1.0. Not backfilled; runs and rescores from now on carry it. No `scoring_version` bump — adding a metric changes no existing score, so cross-experiment comparability holds.
- **Why:** The golden targets average 33.6 words, baseline matched them (33.0), and each fidelity layer added length: keep-the-list ~42, anchor-examples ~42–45, critic-2 ~46–48 (max 94). The optimization loop inflated opinions ~40% past the golden register; length was invisible to the metrics, so nothing pushed back.

### compact-opinions

### critic-2 counterfactual probe (diagnostic, not a prompt experiment)

- **Question:** Why does critic-2 score 0.78 pooled when its generation instructions (RULES.md + rest of prompts.py) are identical to anchor-examples (0.677), and the critic "didn't seem to do much"?
- **Method:** For each of the four critic-2 samples, extracted every `critique_opinion_draft` call from the run traces (agent traces are experiment-parented, so calls map to weeks via evidence ids), matched calls to the final matched-target proposals, re-judged the **pre-critic draft** of every revised proposal with the standard judge, and recomputed the score as if drafts had shipped unrevised.
- **Findings:** REVISE rate 12–18% (10–12 of ~60–65 calls/run). Direct revision lift per run: r1 **+0.000** (0.877→0.877), r2 **+0.088** (0.623→0.710), r3 **+0.025** (0.675→0.700), r4 **+0.042** (0.790→0.831) — mean **+0.04, never negative** (0 hurt cases across 26 revised-and-matched targets; the omission-only design works as built). The saves are exactly the slot-drop classes: W05-02 payoff, W05-04 four-functions statement, W12-01 ownership correction, W04-05 delivery half, W13-04.
- **Mechanism 1 — the critic clips the left tail.** Lift is inversely related to draft quality: zero on the best run (r1), largest on the worst (r2, 0.623→0.710). That is precisely why critic-2's floor is 0.70+ while keep-the-list bottoms at 0.548: the critic doesn't improve good runs, it rescues bad ones. Replicate-mean comparisons understated this; the floor was the real effect.
- **Mechanism 2 — the audience effect.** Pre-critic drafts average 44.4–47.7 words across all four runs — fuller than anchor-examples' *final* opinions (41.6–44.8) under identical writing rules. Even with zero revisions the counterfactual pool {0.877, 0.623, 0.675, 0.790} means 0.741, still above anchor-examples' 0.677. The only prompt difference is the critique tool-use instruction itself: drafting for an omission-auditor produces fuller drafts. Most of critic-2's extra length (~6 of ~8 words over anchor-examples) comes from this drafting shift, not from revisions.
- **Caveats:** counterfactual verdicts were judged in a different session than the finals (~3–6pt judge-session drift on borderline cases); n=4 runs; pool sizes small. The draft-length shift is consistent across all four runs, which is mechanical evidence independent of judge noise.
- **Implications:** (a) "The critic isn't doing much" was wrong in a specific way — its revisions are modest (+0.04) but its presence restructures drafting, and the two together are the +0.10 over keep-the-list; (b) a critic-less variant (e.g. slot-structure) cannot be expected to replicate 0.78 by copying the writing rules, because the edge is the audit step plus the audience effect, not the wording; (c) slot-grammar RULES.md on top of exp/critic-2 is a composable candidate (grammar shapes the draft, critic audits it); (d) for best-of-N, selection plays the same audit role as the critic — the design should preserve the audience effect by telling the agent its drafts will be judged for slot-completeness.
