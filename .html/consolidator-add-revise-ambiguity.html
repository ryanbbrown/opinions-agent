W08-04 · candidate-009

Architecture rule or lifecycle rule?

Eval expects add
Existing opinion-000018

Agent systems should keep the harness thin, put reusable judgment and process in skills, and push repeatable execution into deterministic tools so model improvements compound without making reliability depend on the model.

Generated candidate

As foundation models improve, agent harnesses should usually get simpler rather than more elaborate. Manus's repeated rewrites removed machinery each time; if a harness keeps accumulating complexity while the model gains capability, the harness is probably fighting yesterday's limitations instead of exploiting today's model. Simpler must not mean vague: use clearly structured prompts and canonical examples while letting the model handle edge cases rather than hard-coding them.

Model reasoning: “The candidate adds a useful simplification-over-time rule … while the existing claim preserves deterministic tooling for repeatable execution.”
Why the eval expects add

Expected new opinion: Agent prompts and harnesses should simplify as models improve: give clear structure and canonical examples, but avoid sprawling if-else prompts that try to pre-solve every edge case.

W13-05 · candidate-008

Software verification asset or product-quality asset?

Eval expects add
Existing opinion-000004

Private test suites can be more durable than the generated implementation they verify; SQLite's closed test suite is a clearer moat than its open-source core.

Generated candidate

As AI makes software artifacts cheap to reproduce, “we built it” stops being the moat. Defensibility shifts to information asymmetry: the private eval set competitors cannot score against, the edge cases users actually encounter, and the privately measured ground truth—the target a competitor's optimization loop cannot see.

Evidence owned by this candidate

Why the model chose revise

It treated private test suites, private eval sets, user edge cases, and private ground truth as members of one category: evaluation information competitors cannot copy. It read the candidate as completing the existing moat claim.

Model reasoning: “The candidate completes the existing claim by generalizing beyond closed test suites to real user edge cases and privately measured ground truth.”
Why the eval expects add

The existing opinion compares a private software verification suite with the implementation it verifies. The candidate identifies private product-quality knowledge—real user failures, private evals, and measured ground truth—as a strategic asset. The eval treats those as separate beliefs rather than one broad moat category.

Expected new opinion: For AI products, private eval sets and real user edge cases can be more durable than the product artifact because they define quality against failure modes competitors cannot see.
